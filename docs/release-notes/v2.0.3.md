# v2.0.3 Release Notes

## Human prose and machine evidence

- Clarified the product boundary throughout the app and documentation: human
  prose is written and owned by a person, while JobML supplies explicit,
  evidence-linked detail for ATS and AI systems.
- Renamed the visible Apply flow to Project. Projection selects reviewed ledger
  records and approved prose. It does not submit applications, rewrite prose, or
  infer new evidence.
- Documented optional AI output as a draft or sample. A draft cannot publish
  prose, create accepted evidence, or silently become fact.

## Removed detector-evasion features

- Removed AI-authorship scoring from the resume page.
- Removed the De-AI rewriting service and its UI. lucidRESUME does not attempt to
  disguise generated text as human writing.
- Removed the direct-write translation action, which previously replaced stored
  prose without a separate draft-review step.
- Kept OpenAI, LLamaSharp, Ollama, and Anthropic support for ingestion assistance
  and explicit draft-authoring workflows.

## JobML contract

- Extended the JobML 0.1 specification with the human-authority boundary.
- Confirmed that JobML may retain higher-resolution detail than role-specific
  prose, but every claim must remain traceable to reviewed evidence.
- Updated the manual, architecture, output design, release copy, and Avalonia UI
  scripts to use the same projection terminology.

## Verification

- Complete Release test suite passes: 333 tests.
- The Avalonia XAML compiles for the desktop application.
- Release archives remain gated by the packaged Avalonia UI smoke script. The
  macOS package is also checked with strict code-signature verification.
