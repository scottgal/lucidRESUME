# lucidRESUME 2.6.0

This release fixes job tailoring that could select nearly identical achievements
for different jobs, and adds the lucidRESUME desktop icon and Mac application menu.

## Better job-specific resumes

- Uses the original job description, required skills and responsibilities to rank
  career evidence even when structured competencies or embeddings are unavailable.
- Preserves detailed competencies in the prose brief and includes the complete job
  identity in the prose cache key. Different jobs with similar headings no longer
  lose their distinguishing context.
- Skips unnecessary achievement embedding calls when no usable competency vectors
  are available. Reuses source-bound prose while retaining factual validation.
- Adds a native client regression that generates for two same-title jobs with
  different requirements and checks that their leading achievements differ.

## Desktop identity and Mac release checks

- Adds a shared document/checkmark icon for Windows, Mac bundles, application
  windows and the Dock during `./run.sh Release` development launches.
- Names the Mac menu lucidRESUME and adds About and Settings entries.
- Tests both extracted Mac archives on matching Intel and Apple Silicon runners,
  including SQLite/sqlite-vec migration, vector search, persistence and native
  client workflows. Mac bundles require macOS 14 or newer and are ad-hoc signed.

## Using the update

Restart the application and generate fresh resumes to use the tailoring fix.
Saved archive versions preserve their original output. Back up the complete app
data directory before upgrading, including `data.db`, `generated-resumes/` and
`prose-library/`.

Local validation passed 600 .NET tests and 14 native client workflow groups.
An isolated copy of the complete career produced substantially different evidence
selections for AI leadership, backend and frontend jobs with the writer unavailable.
This verifies selection, rather than a new live-model prose assessment. Stronger
role accounts and outcomes still depend on the author's reviewed evidence.
See the [validation report](../reviews/2026-10-12-v2.5-validation.md) for the earlier
release preparation, follow-up regression checks and coverage limits.
