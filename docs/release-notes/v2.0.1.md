# v2.0.1 Release Notes

## macOS launch fix

- macOS downloads now contain a proper `lucidRESUME.app` bundle.
- Native dependencies, including Avalonia, are embedded in one self-contained
  executable so Gatekeeper cannot quarantine `libAvaloniaNative.dylib` separately.
- The bundle is ad-hoc signed, verified with strict recursive code-signature checks,
  and launched through the Avalonia UI smoke suite before release upload.
- The app is not Apple-notarized. Control-click the app and choose **Open** for the
  first launch; the archive includes an exact per-app quarantine command if needed.

## Evidence projection integrity

- Resume rendering is now a projection of the ingestion-time evidence ledger, not
  an LLM generation or output-time re-inference step.
- Markdown and JobML are emitted from the same stable claim IDs.
- FNV-1a evidence hashes and source revisions detect drift, and stale projections
  are rejected before export.
- Multi-resume imports preserve original document evidence IDs where equivalent
  passages support a merged claim.
- NER and LLM-extracted ingestion records remain review-required.
- Skill IDs now include a stable hash suffix, preventing collisions such as `C#`
  and `C++`.

## Reliability fixes

- SQLite now round-trips user overrides and employer profiles instead of silently
  dropping them.
- Duplicate Markdown evidence anchors are reported as ambiguous rather than
  crashing the live JobML editor.
- Removed a corpus-specific education repair rule from the generic importer.
- Release tags now wait for build, test, and dependency-audit gates.

## Verification

- Full solution test suite passes, including SQLite migration coverage.
- Analyzer formatting verification passes with no warnings.
- NuGet reports no known vulnerable direct or transitive packages.
- The real multi-resume corpus projects successfully to Markdown + valid JobML.
- The extracted Apple Silicon release archive passes the Avalonia `all-pages` UI
  script from its final `.app` layout.
