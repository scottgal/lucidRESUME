# lucidRESUME 3.0.0

## Scientific citations for professional claims

- Published Markdown, Word, and PDF résumés now use compact cJobML citations:
  inline `[n]` markers, a References section, and an optional link to the complete
  JobML ledger.
- Full JobML remains the high-resolution editing and interchange record. It keeps
  prose selectors, evidence fingerprints, drift state, provenance, concepts, and
  review state out of the human document.
- Rendering is a deterministic projection of accepted ledger relationships. It
  never reruns NER, an LLM, embeddings, or claim extraction.
- The new cJobML one-pass parser rejects unresolved, duplicate, orphaned, and
  incorrectly ordered references.

## Linked evidence

- Articles and technical posts can be imported as bibliographic evidence for an
  existing reviewed claim.
- Import records canonical URL, title, author, publisher, publication date,
  access date, and a full-resolution content fingerprint.
- A linked post does not generate a claim and does not silently establish
  production experience, employment, or responsibility.
- `document.complete_ledger` can publish the full JobML endpoint represented by a
  compact résumé.

## Tools and documentation

- Added `lucidresume jobml compact` for deterministic cJobML publication.
- Added `lucidresume jobml link-post` for explicit article evidence linking.
- Added the standalone cJobML 0.1 publication specification alongside the JobML
  specification, schema, implementation profile, and GitHub extension.
- Updated the user manual, output design, README, documentation archive, and
  scientific-publishing article for the full versus compact model.

## Verification

- The cJobML Markdown round-trips through a deterministic parser.
- A gated OpenAI cold-parser test recovers the cited claim, reference number,
  evidence URL, and complete-ledger URL without a JobML-specific prompt.
- Generated DOCX and PDF output retains the prose, numbered citation, reference,
  external URL, and full-ledger URL.
- The generated PDF was checked in the real OpenResume browser parser. Resume
  fields and reference content survived; its fixed schema classified the unknown
  References section as project content.
- The full solution passes 343 tests, including 96 tests for the Avalonia UI
  testing framework.
