# lucidRESUME 2.3.0

## Human prose and machine evidence

- Clarifies the product boundary: lucidRESUME is a career evidence compiler, not
  an automated application service and not a system for manufacturing
  human-looking claims.
- Keeps reviewed human prose authoritative while exposing a higher-resolution,
  evidence-linked JobML representation for ATS and AI consumers.
- Treats optional AI output as a draft. It cannot become accepted prose,
  evidence, or a published claim without review.
- Makes role-specific resumes deterministic projections of the canonical
  ledger. Rendering never re-infers experience from prose.

## Full career records and JobML

- Adds the portable JobML `career_record` profile for complete career
  transcripts, sources, claims, review state, evidence selectors, drift hashes,
  concept embeddings, semantic spaces, and role centroids.
- Adds stable, immutable full-record publication endpoints and a link from
  compact output to the complete record.
- Extends JobML with typed extension data for repository and package-registry
  observations while keeping those observations separate from accepted claims.
- Adds author-selected career anchors so important historical roles can remain
  visible without pretending that employer prestige is an inferred score.
- Strengthens validation for machine-derived review state, stale evidence,
  missing references, legacy endpoint aliases, and extension round trips.

## Scientific-style resume output

- Adds inline numbered citations and a compact JATS-inspired cJobML References
  section to Markdown, Word, and PDF output.
- Keeps long selectors, quoted passages, hashes, embeddings, and detailed
  provenance in full JobML instead of bloating the human resume.
- Supports an optional public full-JobML endpoint plus direct links to roles,
  projects, repositories, articles, qualifications, and other evidence.
- Improves DOCX and PDF pagination so references remain compact and usable by
  ordinary ATS parsers.

## ASP.NET Core resume compiler

- Adds `lucidRESUME.Web`, a minimal ASP.NET Core control that publishes a
  validated complete career record and compiles it against a pasted job
  description.
- Publishes content-addressed immutable JobML revisions with ETags and a stable
  current endpoint.
- Selects, orders, and fits complete human-authored sentences to compact section
  budgets before any optional prose pass. A matching role is a selective account,
  not a dump of every matching ledger claim.
- Supports bounded `Tighten` and `HumanVoice` passes with OpenAI or local grug 9B.
  Edits are validated and accepted per section, so one bad section cannot discard
  useful work elsewhere. Unknown claims, evidence IDs, numeric facts, unsupported
  vacancy terms, or over-budget prose retain the last valid human-based section.
- Batches local-model sections for document-level coherence and safely recovers
  only complete section objects when a constrained JSON response is truncated.
- Protects the reviewed professional summary from model rewriting, renders
  employment in reverse chronology, and prints the parsed target title.
- Restores conventional ATS-visible `Core Skills` and education sections without
  copying vocabulary from the vacancy. Skills are canonical JobML concepts
  attached to claims that survive into the rendered projection; the advert only
  ranks them. Category quotas prevent a concept-rich project from hiding
  leadership and delivery evidence.
- Gives senior targets a bounded preference for reviewed productisation evidence,
  allowing Head, VP, and CTO projections to differ from hands-on Lead output.
- Exports the same projection as Markdown, DOCX, and PDF, with optional cJobML.
  Selected engineering projects retain their compiler order ahead of employment
  history in all three formats, rather than being pushed behind education.
- Requires authenticated writers by default, validates antiforgery tokens, caps
  uploads, and does not fetch URLs embedded in uploaded JobML.

## Import and parsing

- Adds deterministic Markdown parsing for complete transcripts, conventional
  experience headings, compact role lines, current roles, and additional date
  forms.
- Adds a `Reviewed` import mode for a human-checked complete transcript. Its
  contact details, role identity, and dates can deliberately supersede stale
  imported variants while the original source evidence remains unchanged.
- Routes every desktop import through an explicit per-source merge review and
  adds persistent editing for reviewed role dates and identity fields.
- Adds bounded parsing decisions after deterministic rules and NER have already
  produced candidates. A decision provider can select an extracted name,
  employer, or section classification but cannot invent a new value.
- Adds experimental Jev-assisted entity and section decisions with probability
  thresholds, source hashes, review records, and reproducible benchmarks.
- Allows a separate extraction provider, so local GGUF parsing can be combined
  with a different optional drafting provider.
- Extracts title-shaped leading sentences from flattened pasted adverts without
  depending on optional NER assets being installed.
- Adds a parsing benchmark project and fixtures for entity resolution and
  section classification.

## Repository and package evidence

- Expands GitHub import into an explainable repository audit containing fork and
  archived status, repository age, active span, recency, licence, tests, CI,
  release automation, package manifests, documentation, and browser-extension
  structure. Deeply inspected repositories include an immutable revision;
  inventory-only records explicitly report an unknown revision.
- Retains small repositories and forks as observations, but excludes
  unattributed forks and repositories below the evidence threshold from
  personal skill claims and resume selection by default.
- Separates originality, longevity, engineering-process, documentation, and
  delivery dimensions. Stars and forks remain popularity observations and do
  not increase evidence strength.
- Uses stable provider-derived project IDs and refreshes audits in place.
  Existing human project prose is preserved when matching repository metadata is
  attached.
- Adds NuGet publisher audits using public profile inventory and official V3
  metadata. Related package IDs are grouped into searchable product families;
  download counts remain time-stamped registry observations, not competence.
- Adds full JobML specifications for GitHub and package-registry extensions.

## Chrome evidence filler experiment

- Adds an experimental Manifest V3 Chrome extension that reads a published
  JobML endpoint and proposes answers for visible, empty application fields.
- Uses Chrome's on-device Prompt API for semantic field mapping where available.
  Normal code validates evidence IDs and exact source substrings before any
  value can be filled.
- Never submits a form, never overwrites non-empty fields, and leaves salary,
  sponsorship, work-authorisation, demographic, consent, and unsupported custom
  questions as explicit gaps.
- Includes deterministic identity fallback, local unit tests, a Greenhouse,
  Lever, and Workable form-shape matrix, an opt-in real Prompt API smoke test,
  privacy documentation, and a clear prompt-injection warning.
- The release workflow now builds, checks, tests, and packages the unpacked
  extension as a separate experimental download.

## Desktop and security

- Adds local operating-system credential storage for cloud API keys. Keys are no
  longer written to the JSON settings file.
- Adds OpenAI settings and bounded ingestion support while retaining Anthropic,
  Ollama, and experimental LLamaSharp paths.
- Adds Public Software Evidence controls for GitHub and NuGet, including clear
  counts for eligible, observation-only, and deeply inspected repositories.
- Re-imports refresh machine observations rather than leaving stale repository
  or package metadata in the ledger.
- Adds UI controls for selecting career-anchor roles and persists those choices.
- Adds a contact preference field and renders it after the phone number in human
  Markdown, Word, PDF, and full career-record output without contaminating the
  machine-readable phone value.
- Makes explicit role end dates win over a stale `Present` marker during
  multi-resume merging, irrespective of import order.
- Disposes CLI dependency containers deterministically, preventing native model
  sessions from failing during process shutdown.

## CLI

- Adds `jobml career-record` with optional GitHub and NuGet enrichment.
- Adds `jobml compact` support for a public full-JobML URL.
- Adds JSON repository-audit output to `github-import`.
- Adds `package-audit` for public NuGet publisher inventories and package
  families.
- Keeps API credentials in configuration, environment variables, user secrets,
  or the operating-system keyring. No credentials or personal ledger snapshots
  are included in release archives.

## Documentation and research

- Expands the JobML 0.1, cJobML 0.1, GitHub extension, package extension, web
  compiler, output-design, browser-extension, and user-manual documentation.
- Adds a sourced resume-format and ATS compatibility review.
- Adds Jev parsing research, benchmark instructions, Chrome Prompt API privacy
  and threat-model notes, and current limitations.

## Validation

- 479 .NET tests pass across 12 projects, including 98 Avalonia UI-testing
  framework tests.
- A clean Avalonia quality loop imports four resume variants plus a reviewed
  complete transcript, verifies corrected contact details and chronology, and
  compiles Lead Developer, Head of Engineering, and CTO projections with
  optional cJobML.
- Live end-to-end validation imports 53 public GitHub repositories, retains 13
  observation-only records, groups 175 public NuGet package IDs into 24 product
  families, and emits a valid full career-record JobML document with all 53
  repository observations.
- Full JobML validation reports no errors and no unresolved prose references;
  machine-derived candidate claims remain explicit review diagnostics.
- Desktop and CLI builds complete with zero warnings and zero errors.
- The Chrome extension TypeScript checks, unit tests, build, and local form-shape
  fixtures are release gates.

## Upgrade notes

- This is a minor release in the existing 2.x line.
- Existing local SQLite data remains supported. New career-anchor and project
  evidence metadata is additive.
- Re-run GitHub and NuGet audits after upgrading to populate the new structured
  observations and stable IDs.
- The Chrome extension remains experimental and must be loaded unpacked. It is
  not published to the Chrome Web Store.
- macOS archives remain ad-hoc signed rather than Apple-notarized. Follow the
  per-application Gatekeeper instructions included with the archive.
