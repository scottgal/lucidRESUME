## Issues found and addressed

- New source files failed CI formatting; the solution was formatted without changing
  the pre-existing pointer compatibility patch.
- An indirect ImageSharp 3.1.12 dependency raised advisories. The newer image package
  required a vendor licence. The application now applies the vendored summarizer's
  intended text/BERT-only compilation at restore/build evaluation time, excluding
  unused image/PDF/code-analysis dependencies without editing the submodule. The
  app's own DOCX/PDF import and rendering paths pass the native checks.
- Windows CI found pooled SQLite handles surviving store disposal and locking temporary databases. The single long-lived store connection now disables pooling, with a regression asserting file release after disposal.
- Windows native validation exposed a test-harness encoding mismatch: the MCP server
  emits UTF-8, including a byte-order marker, while Python defaulted to a Windows code
  page. The first response was valid but discarded, causing timeouts. The subprocess
  and diagnostic logs now explicitly use UTF-8; corrected local and Windows runs passed.
- Seven exercised CLI workflows wrote output then failed during synchronous DI
  disposal of an async-only scraper. CLI handlers now await service disposal.
- Pipeline visual review found that all timeline events displayed an `auto` label.
  The badge now depends on the stored automatic-event flag.
- Release docs packaging omitted the new transcript/workflow guides and screenshots.
  They are now included. Backup guidance now includes archive files, not just SQLite.

The local native input checks include the existing Avalonia 12 pointer input-root
compatibility change in the working tree. That change was preserved unchanged and
must be included in the source used for the release.

## Reproduce locally

Use new output directories for each native run. The scripts use isolated state and
synthetic inputs; they do not mutate the user's live career or send messages.

```bash
dotnet restore lucidRESUME.sln
dotnet build lucidRESUME.sln -c Release --no-restore --warnaserror
dotnet format lucidRESUME.sln --verify-no-changes --no-restore --severity warn
dotnet test lucidRESUME.sln -c Release --no-build
dotnet list lucidRESUME.sln package --vulnerable --include-transitive
python3 scripts/validate-release-cli.py --output artifacts/cli-e2e
python3 scripts/validate-release-client.py --output artifacts/native-e2e
```

On Linux, install the desktop libraries listed in CI and wrap the native command
with `xvfb-run -a`. A real display is used on macOS/Windows. For a self-contained
payload, pass its executable using `--app`.

Start the sample web compiler on loopback with isolated snapshot/publication
directories and local writes enabled, then run:

```bash
python3 scripts/validate-release-web.py --output artifacts/web-e2e
```

The web validator refuses non-loopback hosts. Each validator writes `report.json`
and logs; the native validator also captures real UI screenshots. The CI workflow
uploads these records even on failure. Compatible macOS release runners execute
the native validator against the ad-hoc signed `.app` launcher.

## Publication and explicit coverage limits

- Final-source CI passed on Windows, Linux and macOS. This host also validates macOS
  arm64 locally; cross-platform execution is provided by the linked CI runners.
- All six archive builds and compatible signed macOS bundle checks passed. Ad-hoc
  signing is not notarization or a launch check of every archive architecture.
- Actual Word page rendering passed on the local macOS host and the Windows CI runner,
  with rendered pages visually checked. Linux CI lacks a Word
  renderer and exercises the explicit unavailable-renderer fallback; a passing native
  workflow there must not be interpreted as successful Word page rendering. PDF page
  previews, saved DOCX files and evidence links are checked independently.
- Live authenticated IMAP, private GitHub/NuGet accounts, job-board API credentials,
  cloud writers and optional Nimble/Cloudflare decision endpoints were not exercised.
  Their deterministic rules and mocked provider contracts are covered by the .NET
  suite. Do not describe them as live end-to-end validated.
- The large private full-career Morena regression was exercised earlier in this
  development session. Its cold/repeated prose timings are observational, and its
  evidence gaps still require author answers. Synthetic release checks do not
  establish that every real-world resume will be well parsed or well written.
- Native file-picker-driven backup/export interactions were not automated; archive
  output, CLI exports, persistence and document rendering were exercised. Archive
  metadata alone cannot restore missing document files.
